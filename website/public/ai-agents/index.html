AI at work / the basics

What is an
AI agent?

An AI agent is software you give a goal to, along with information and tools it can use to get there. It can decide what step to take next without you prompting every move.

See how it works ↓
01 / The difference

It can take the next step.

In a simple chat, you provide the material and ask a question. An agent can use connected tools to find information, work through several steps and produce a result. Depending on how it is built, it might search documents, update a record or send a message. It may pause for approval, or it may keep going on its own.

Goal→Approved information + tools→Steps→Result
02 / A work example

Preparing for a customer meeting.

You could paste notes into a chatbot and ask it for a summary. An agent could find the approved meeting notes and account information itself, pull together a brief, then hand it to you to review.

That saves you the search. It also raises two useful questions: what could it read while preparing the brief, and where could that brief go afterwards?

What does that give you?

Less time spent gathering information, a more consistent first draft and more time to focus on the conversation itself. The useful part is the handoff: the agent prepares the brief, and you check the details and decide what to do with it.

03 / Getting started

How do you make one?

Start with one job. Define what a good result looks like, connect only the information and actions needed for that job, then test the agent's behaviour before people rely on it.

Slack

Build an agent that works where your team talks. Start with Slack's agent quickstart.

Agentforce

Build an agent around Salesforce work and bring it into Slack.

Anthropic

Use Claude to build an agent with instructions and tools. Follow Anthropic's managed agents quickstart.

OpenAI

Build an agent that can work through steps and use tools. Follow OpenAI's Agents API quickstart.

These are starting points, not four separate types of agent. For example, a custom Slack agent can use Anthropic or OpenAI behind the scenes.

Whichever route you take, choose its permissions deliberately. An instruction saying “don't share this” is no substitute for limiting where it can actually send data.

04 / Two different risks

Whose agent is it?

Your own agent might go beyond the job you intended because it can read too much, take too many actions or send its work to the wrong place. You can set limits on those permissions and review what it does.

Someone outside your business can also use an agent to automate parts of an attack against your systems. You cannot pause their agent. You need your own access controls, monitoring and response plan. Treat these as separate problems.

Before you connect one to work

Ask what it can read, change and send.

Then ask who approves those permissions, who sees its activity and who can stop it. Those answers matter more than how impressive the demo looks.
